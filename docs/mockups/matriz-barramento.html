Matriz de barramento: cada acontecimento contra cada cadastro

No método Kimball, todo dado de análise é um fato (um acontecimento: um fechamento, uma ronda, a geração de um dia) ligado a dimensões (os cadastros de referência: usina, pessoa, data…) por um ID. Quando dois setores usam a mesma dimensão pelo mesmo ID, os dados deles se cruzam sem conversão. Esta é a foto dos 14 processos que existem hoje, lida do cabeçalho de cada livro do banco.

FatoUma linha = um acontecimento. Tem números (nota, kWh, minutos) e os IDs de quem, onde e quando.
DimensãoO cadastro de referência, com um ID nosso. É o mesmo para todos os setores: uma usina só.
GrãoO que exatamente é uma linha do fato. Sem ele escrito, dois relatórios contam coisas diferentes.

PASSO 1 · ESTA PÁGINA

Grão de cada livro escrito

A tabela acima diz o que é uma linha de cada fato. Vai para o CLAUDE.md de cada área, e livro novo só entra no banco com o grão e as dimensões dele declarados.

PASSO 2

Fato gravado com os IDs

O Nexus lê cada livro de origem e grava o fato já com usina_id, pessoa_id, data e equipamento. Começa pelos fechamentos do App: a pessoa já liga em 95% pelo código, e a usina pelo código do ativo e o de-para.

PASSO 3

Uma dimensão de cada

A usina do cadastro vira a única (as outras três passam a apontar para ela), o equipamento nasce do gêmeo (que já tem a lista e os apelidos por sistema), entra a dimensão de data, e a pessoa ganha histórico de equipe e supervisor.

Vale para a camada de indicadores, previsão e diagnóstico (ranking, triagem, perdas, geração, PCM). As telas operacionais (fila da Aprovação, cadastro em edição) continuam lendo o registro vivo. O banco é a API de planilhas: o modelo vale igual, e a junção continua sendo feita no Nexus, pelo ID.
